# 事件计价实跑任务卡

采用《长程智能体冗余阶段奖励设计_原始方案修订版》。本阶段用已验证的 BrowseComp-Plus / Qwen3.5-9B 生成后端验证修订方案。工具事件接口可供其他任务适配器使用。

- 记录每次调用的原生策略 token 坐标、首次确定标签的轮次和实际追加返回的 token。无明确归属的思考 token 不参加事件扣分。R2b 核对同一轨迹中更早一次成功返回的相同工具、结构化参数和原文结果。较早结果须已出现在收到模型响应的请求中，回填晚于重复动作的结果不构成该动作的证据。
- 已执行的末轮工具调用若因原生上下文保护而未发出下一次模型请求，保留调用和原生生成成本。仅当未发送回执能绑定同批结果时，追加到已发送模型输入的返回 token 记 0。
- 逐 token 字节日志有空项时，调用区间仍须由连续的原生字节界定。工具调用文本须与原生 completion token ID 解码的结果逐字节一致。调用内部缺字节时保持未计量。
- 按同题其他样本的结果分均值作基线。结果分包含可核验的取证加分。成功同伴开启局部扣分，完整记录的预算截断可计价，全错组自然产生零优势。工具故障或日志缺失排除整组。
- 价格由冻结参考批的事件成本中位数缩放，事件成本由生成 token、返回 token 和调用次数相加。上限为单事件两倍、单轨迹 0.5。损失分母固定为计划样本数乘以 4096。
- 五个对照从同一初始模型、同一新生成训练批各做一次更新。按已有 P0 批次的通过率选择 20%–80% 的训练题。评测沿用独立的固定 16 题、每题 8 条。数值目标完全相同的实验臂共享该工程结论并明确记录实际执行情况。
- 一步实跑直接测试目标价格。训练配置支持零价预热和线性爬坡。R2b 初价 0.10。R1 与 R2a 保留诊断，待删除及人工标注能验证精确率、B⁺ 标记率和污染率后进入计价。均匀对照采用预设 0.02。
- 更新后从核对过字节摘要和文本参数集合的推理快照冷启动四个 Actor。四个权重指纹与生成探针通过后评测。保留旧作业、旧目标和失败记录。
- 按 Slurm 规则运行。控制文件在 persist，轨迹、模型、检查点、报告、日志和缓存放在 bulk。保持四卡、24 CPU、384G 的正式申请。Judge 使用已有官方 DeepSeek 密钥文件。结果与过程核对隔离，过程标签只使用当时可见证据。

## 分阶段训练入口

每个 Slurm 作业采集一个新训练批并执行一次更新。用 `sbatch <冻结源码>/scripts/hf_pilot.sbatch <冻结源码> <阶段配置.json>` 提交。以下配置举例采用一步预热和两步爬坡。

1. `price_schedule` 设为 `{"update":1,"warmup":1,"ramp":2}`，从 P0 执行公共 Outcome 更新。预热期间仅使用任务结果分，过程 Judge 不发请求。
2. 将 `update` 改为 `2`，`resume_from` 指向公共 Outcome 的 `checkpoints/step-0001`。从对应推理快照冷启动并重新采集训练批。各臂独立恢复同一模型、Adam 和随机数状态，价格乘以 `0.5`。将配置中的 P0 缓存评测项去掉，重新评测续训起点。
3. 将 `update` 改为 `3`，每个配置只指定一个实验臂和其自身的 `checkpoints/step-0002`。沿用冻结的计价、信用分配与校准配置，价格达到目标值。继续从各臂的新快照采集数据。

阶段入口校验上一阶段的持久化记录、四份状态分片、推理快照和已消费批次的摘要。续训时每个 rank 记录 Adam 步数。作业 182516 是独立的一步试验，阶段间四卡恢复需要另行实跑验证。
