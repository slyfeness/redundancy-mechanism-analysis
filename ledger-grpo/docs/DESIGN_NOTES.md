# 实现范围、设计修正与验收边界

本文件说明本包与《长程智能体冗余阶段奖励设计_原始方案.md》的重要差异。这里的“算法 v1”指第一阶段的保守奖励方案；它与 verl 新版的“trainer v1”不是同一个概念。本包的训练桥目前只针对固定官方提交的 verl legacy v0；具体入口和限制见 [VERL_INTEGRATION.md](VERL_INTEGRATION.md)。

## 当前实际支持的识别范围

| 类别 | 当前实现 | 进入奖励的条件 |
|---|---|---|
| R1 已有事实重复核验 | 已有显式支持、可追溯来源、无新记录信息，加局部语义核对 | 局部核对返回 yes，并引用先前与当前证据；无核对器时弃权 |
| R2 同缺口重复尝试 | 同目标、同方法、规范化查询匹配、重复文档且无记录进展 | 默认仅精确规范化查询；可配置词集合相似度，未实现语义 embedding |
| R3 重复展开判断/计划 | 同 decision_key、无中间工具行动且账本未变化 | 仅诊断，不进入奖励 |
| D1 使用已反驳前提 | 行动显式指向账本中的 refuted fact | 仅供审计；尚不证明因果错误 |
| D2 必需约束缺乏支持 | 提交时所选候选有必需约束未获记录支持 | 仅诊断；第一阶段通过 grounding 轨迹分量表达，不再局部重复扣罚 |
| D3 冲突后仍沿用候选 | 行动显式指向仍有未解决反驳的候选 | 仅供审计；尚未区分继续调查冲突与固执沿用 |
| D4 产物未落实 | 必需产物提交版本与此前观察到的通过自测版本不一致 | 默认关闭；识别端与打分端均须显式启用，且仍受 QA 和结果组规则约束 |

搜索任务上的一般“判断未落实”、跨轮反事实删除、多模型投票、模型校准、按预算调整策略及蒸馏均尚未实现。`phase` 是配置记录字段，修改字符串不会自动打开二期标签。D1–D4 的权重字段也不代表这些类别均已启用。当前 D4 的数值权重由 `score_batch` 从配置传入 span 映射；直接调用映射函数时需要显式传 `d4_weight`，默认 0.15。

判别单位采用显式 turn 与原生策略 token 区间。代码不会根据文本长度猜 tokenizer 偏移，也没有自动完成所有数据集原始格式到标准轨迹的转换。工具返回、上下文和 padding 的 mask 必须为 0。多个 R span 重叠时取最大置信度，不重复累加；已启用的非零 D4 偏移优先于同位置 R。

## 账本提供可审计的判断，不提供真值

独立结果验证器提供 `outcome=0/1`；judge 不可通过来源文本、自己的结论或金标替代结果验证器。抽取器只接收当前可见的信息；特权字段不进入冗余判别。任务约束须由数据适配器显式提供，不从答案反推约束。

引用核验检查证据 ID、可见时间、原文子串和可选字符区间。这些检查只能证明“引用真实存在”，不能证明原文蕴含事实、原文可信或事实就是外部真相。实时 supported/refuted 抽取还要求局部 support 核对器确认；该核对本身仍是模型判断。人工/fixture delta 回放不等于独立语义验证，报告保留 `semantic_calibration=not_established`。

来源标识必须由适配器可靠提供。`source_id` 的不同字符串只是程序计数的依据，不会自动证明两篇文章彼此独立；重复抓取不能靠换 evidence_id 变成新证据。文档键结合来源、文档、版本、展示形式和内容哈希，摘要升级全文以及真正的新版本被保护。缺失 source_id 不会被默认视为可靠的独立来源。

规则产生的 `confidence=1` 表示当前规则谓词满足，不是校准后的概率。显式独立试验、合理重试理由、新文档/版本或账本进展会阻止相应的冗余标记；这些保护条件也依赖适配器和抽取质量。

## QA、缺失值和无效训练组

抽取缺失或解析失败视为 unknown，不视为“没有信息增益”。单条轨迹的过程 QA 失败会停用其所有过程 span；优势计算再对整个同题组关闭效率、grounding 和局部偏移，保留独立结果信用。这样不会把失败解析所产生的 0 当作正常样本参与过程分量归一化。

高层 `build_process_inputs/score_batch` 还采用一条保守策略：若 grounding 无法计算，例如搜索任务未给出提交候选，`process_valid=False`，从而同题组所有过程分量停用。行内存储的 grounding 占位 0 不参与该组过程归一化，不能解读为已知的零分。低层 `compute_advantages` 支持 `grounding=None`，含义仅为停用 grounding 分量，R 和效率仍可计算；这两层的缺失值策略刻意不同。生产数据路径应保留高层的 `process_valid`，不能仅复制占位分数。

训练有效性与过程 QA 分开：任一成员不完整、被声明无效或没有策略 token 时，整题组退出训练；全错组也在任何 D 偏移之前丢弃，不能从全错组中制造相对过程奖励。完整组的信息必须先汇集，再做条件归一化和统一批级缩放，不能按 rank 或 microbatch 独立估计。

离线 `score_batch` 可以返回全零有效 mask 供审计；训练端必须检查这一状态。`apply_to_batch` 在全批无有效行时抛出 `NoValidTrainingRows`，阻止 optimizer 继续执行。部分无效行保留形状、清零训练 mask，原始 mask 另存审计；当前要求 token-mean，真实 runner 仍须移除无效组、补采样并避免全零微批次。插件没有实现这些训练调度行为。

## 数学约定与原文字面差异

默认 `process_enabled=False`，只计算结果分量；并未自动根据准确率平台打开过程奖励。开启、升权与验收由外部训练计划决定。

标准差使用样本标准差；单样本或常数分量产生零相对信号，退化批次不放大极小数值。效率与 grounding 只在同组至少两个答对样本间比较。裁剪后的 z-score 不一定仍为零均值，因此原方案“各分量本就是零均值”的文字解释并不总成立；代码保留规定的裁剪并只做批级缩放，不额外重中心化，元数据记录实际均值。

混合组的符号锚定按实际组大小及数值结果检查严格界限；默认权重和为 0.25，在 G=16 的严格界限处会被拒绝。该约束只保证满足条件的混合组轨迹级符号；全对组可以有负相对优势。R 只缩小答对轨迹的正优势，负优势不被 R 再压低。D 在 R 后使用共享的下降预算；`beta=0` 不新增跨零下调，但不会把本来为负的全对组优势恢复到零。

这些局部约束不构成训练后准确率保证。是否满足“准确率下降不超过阈值”、是否更省、是否减少欠核验，必须通过独立任务评测、重复种子、配对统计和人工审计检验。评测工具只计算输入数据的统计量，不执行任务、不生成新实验结果，也不自动批准训练。

## 对照与停止建议

离线接口和 verl 桥均提供 targeted、同额 uniform、token shuffle 与仅轨迹级 trajectory。对照操作在有效策略 token 内进行，更新 advantages 和 returns；桥接通过 `ledger_span.control/seed` 显式选择并记录。当前 shuffle 只保持 token 偏移多重集与总量，**不保持连续 span 的数量、长度、标签或 turn 边界**。原方案的完整“打乱 span”对照及按 turn 均匀对照仍须另行实现。

G 状态只给诊断与建议，不强制 stop。饱和判定默认未开启；开启后必须由调用方提供次数阈值，其含义仍是同方法、近重复尝试且无记录进展，不能证明未来搜索价值为零。建议 submit/continue/pivot/review 不直接变成奖励，也没有接入在线停止控制器。

## 当前验证结论

本轮验证覆盖本地 CPU 张量计算、规则和标准化数据契约、配置路由及轻量 DataProto 兼容对象。另通过 DeepSeek 官方 API 运行六个合成局部案例，全部匹配预期，证明接口与这些简单案例可以运行；它不构成长轨迹 judge 校准。没有部署本地 judge、安装和运行真实 verl 训练栈、进行训练更新、集群/GPU 实验或多节点验收。真实来源独立性、judge 精确率、B+ 污染率、token 对齐与训练收益均仍需实测。能够导入插件、通过兼容对象单元测试、完成真实训练验收是不同状态。
