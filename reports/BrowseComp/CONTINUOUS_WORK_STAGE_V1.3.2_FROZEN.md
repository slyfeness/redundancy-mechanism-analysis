# CONTINUOUS_WORK_STAGE V1.3.1 FROZEN

以下完整继承V1.3冻结规则，文末列出本版补充判定。

# Codex通用规则：按实际思维动作划分Stage
版本：V1.3_CANDIDATE；本次执行冻结
用途：依据原始轨迹按真实思维动作划分Stage，不改变原始字段或时序。

## 一、核心定义

Stage是原始轨迹中一次连续、相对完整的局部思考或取证动作。

判断的是“模型这一次具体在做哪一步”，不是“这一大段最终都在解决哪个问题”。同一个信息需求可以对应多个先后发生的Stage。同一种动作再次实际展开，也可以形成新的Stage实例。

只输出时间序列：Question → S001 → S002 → …… → 正式Final。不建立树状结构，不预设Stage数量、长度或工具次数。

## 二、边界判定

### 1. 同一动作内部保持完整

同一次论证、计算、候选比较或取证尝试内部的材料、解释、推导和局部结论保持完整。不能将一次完整比较机械拆成“列证据、做计算、下结论”。不能按句号、换行、列表、关键词或字段类型切分。判断能否合并时，必须说明它们为什么属于同一次动作，不能只说“仍然在找同一个答案”。

### 2. 实际开展另一项思考动作时切分

模型真正开始以下工作时，应审核新边界：

- 对一个具体候选展开实质核验、比较或排除。
- 从局部事实核查转入完整的证据充分性或答案接受判断。
- 从已有判断转入独立纠错、重新推导或另一个条件核查。
- 实际编写答案草稿。
- 在判断或草稿之后重新展开核查。
- 结束一次取证尝试后，重新选择并执行下一次取证。

这些是需要识别的实际行为，不是强制套用的固定阶段模板。“出现一个候选名”“说了一句准备回答”“列出一个未来待办事项”本身不自动构成新Stage。

### 3. 同一信息需求下，也要区分不同取证尝试

一次取证通常包括：本次查询的实质准备或选择 → 实际Call → 完整Return → 对本次结果的直接处理和局部评价。

如果本次结果已经得到评价，模型随后重新决定查询、改换证据入口或重新发起核查，应审核为下一次取证Stage。即使再次使用相同查询、仍未获得新信息，也不能仅因目标相同就把不同执行实例全部合并。

但不能实行“一次Call必定一个Stage”：同一联合决策下的批量查询、没有新决策的自动翻页、同一次操作的协议步骤，应保持完整。判断依据是“前一次尝试已收束，下一次尝试实际启动”，不是Call计数或Round变化。

### 4. 已展开的整体判断，不因后来继续搜索而消失

如果模型实际比较多项证据，评估是否足够回答，接受或排除候选、形成答案判断，应保留这次认知工作。后来又搜索、改主意或没有提交Final，不构成取消该Stage的理由。

仅为说明当前缺口而简短复述背景，仍可留在取证Stage中。区分两者时看是否实际展开判断，不以“后面有没有继续搜索”作为裁决标准。

### 5. 保留真实的中断、恢复和重新执行

A工作 → 实际展开B工作 → 恢复A工作，应保留三个时间连续的工作实例。不能跨过B合并前后A。

同一段未被打断的解释换一种说法，不自动算重启；已完成一次判断后重新核验、重新推导或重新草拟，则需要检查是否开始了另一次实际动作。

动作可以失败、被中断或形成未执行计划。实际比较路径、设计查询并作出选择，本身也是认知工作；但不能把仅被提及的未来任务标成已经执行。

### 6. 工具调用和返回属于相应动作Stage

每个真实Call及其完整Actor可见Return，必须完整、唯一地归入对应取证Stage。不额外建立工具层级。不因缺少紧邻的“让我搜索”一句话就机械创建工具Stage。

确实没有显式前置推理时，根据实际查询及上下文记录动作，不补写隐藏动机；必要时Stage从真实Call位置开始，并继续包含其完整返回及直接结果处理。

同批工具保持原始批次关系，不得虚构“看完同批第一个返回才决定第二次调用”。返回后的推理若已经开始独立候选评估、整体判断或新取证，应在实际转换处另切，而不是把所有后续思考都并入搜索。

### 7. 精确确定新动作的起点

先判断是否发生动作转换，再定位原文位置。上一动作的直接结果解释、失败反馈和局部结论留在上一Stage。下一Stage从新动作最早实际展开的位置开始。

同一Round可以包含多个Stage。一个Stage可以跨Round承接自己的工具返回及直接结果处理；跨Round不是禁止项，也不是持续合并的理由。

若Stage从工具开始，起点必须记录为该Call事件，不能只填写下一轮reasoning的起点。代码、工具参数、引用及完整工具返回不得从中间切开。

## 三、固定工作流程

1. 完整理解。阅读Question、全部原始推理、实际Call/Return及正式Final，先写出模型实际的求解过程，不参考旧Stage数量或切点。
2. 写出动作序列。沿时间顺序描述每次实际工作：“针对什么对象，做了什么，本次得到什么局部结果或结束状态”。不能先写“探索—核验—回答”三个大标签再往里装原文。
3. 确定边界。每个候选切点回答：前一动作如何收尾或被中断？后一动作具体开始做什么？为什么不是前一动作的内部展开？然后决定KEEP（保持）或SPLIT（切分）。
4. 双向复核。对每个Stage检查是否吞并多次实际思考或取证动作。对相邻Stage检查是否切碎同一次论证、比较或查询准备。不用“同一信息需求”单独证明KEEP，不用“换Round、出现转折词或新Call”单独证明SPLIT。
5. 映射原文与工具。保存真实Round、逐字段Unicode字符范围[start,end)、完整推理及工具事件、Stage起止位置。每次Call/Return只归属一次，不重排，不跨段拼接。
6. 机械验收。核对原文覆盖、无遗漏重叠、逐字段还原与SHA、调用及返回配对、参数、批次、执行顺序、首次可见时刻及正式Final分离。

语义判断由阅读原文完成；脚本只负责定位、组装、保真检查与排版。

## 四、验收重点

- 能看见真实发生的局部核查、候选判断、整体评估、答案草拟和重新取证，而不是只剩几个调查方向。
- 同一次论证或取证的内容没有被机械切碎。
- 工具调用及完整返回已经包含在相应动作Stage中。
- 重复发生的动作按时间保留，不因重复而合并消失。
- 不为后续删除实验制造切点，不预先判定Stage冗余。
- 合理歧义简记主方案与备选，不强求所有边界唯一。

## V1.3.1 补充判定（冻结）

### 局部取证反馈与独立整体判断

对某次工具返回的直接解释、局部结论，归属该次取证Stage。如果模型随后实际展开多条件比较、证据充分性评估、候选接受或排除、完整答案判断，应另建Stage。即使没有新工具调用，实际发生的独立认知工作也必须识别。

### 避免机械过度切分

简单复述已知条件、列举缺口或解释单次查询结果，不自动形成新Stage。只有实际展开不同思维动作，才SPLIT。不能仅凭完整清单、转折词、Round或Call数量决定边界。

### 强化双向审核

对每个包含工具返回和长篇后续推理的Stage，检查是否遗漏独立判断或答案构造；对每个新增边界，反查是否只是同一次取证的自然延续；精确定位新动作最早开始的位置。

# V1.3.2 候选补充：思维动作转换与相邻Stage合并判定

本候选继承以上 V1.3.1 全部既有规则；不改变原始轨迹、工具协议和时间顺序。V1.3.2 尚待研究者审核，不改变 V1.3.1 冻结状态。

## 1. 区分信息需求与实际工作实例

**信息需求（Information Need）**是模型尚未解决的问题或证据缺口。

**Stage**是为解决任务而实际展开的一次连续、相对完整的局部思考或取证工作。

一个信息需求可能对应多个Stage。

判断是否合并时，不能仅以两个片段解决相同信息需求为依据，必须检查其间是否发生了实质思维动作转换。

## 2. 优先识别已经完成的独立认知工作

出现以下实际行为时，应检查是否建立新的Stage：

- 对具体候选开展独立、实质性的比较或排除。
- 对已有证据进行完整条件判断、证据充分性评估或答案接受判断。
- 发现原假设存在问题，实际重新推导或修正判断。
- 已经完成一次判断后，重新选择并开展另一项取证工作。
- 实际形成答案草稿，或在草稿之后再次展开核查。

这些动作即使发生在同一个Round、服务于同一信息缺口，也不能因此被合并。

但简单复述已有结果、列举待查条件、尚未执行的备选计划，不自动成为新Stage。

## 3. 区分实质取证转换与普通搜索重试

**倾向SPLIT：**

前一次结果已经得到处理，模型随后实际重新选择核查对象、证据入口、候选假设或验证方法，并开展新的取证工作。

**倾向KEEP：**

模型没有展开新的候选判断或实质决策，只是沿用相同取证计划，重复调用工具、微调关键词或继续执行同一操作。

上述标准均须由原始推理和真实工具行为支持，不能仅凭查询字符串相似度或Call数量判断。

## 4. 对跨多次工具调用的Stage进行专项审核

允许一个Stage包含多个真实Call及其完整Return。

但如果Stage中存在多个工具返回后的思考片段，必须检查：

1. 是否发生过完整候选评估或实质判断。
2. 是否形成过新的取证决策。
3. 是否从一个验证对象或证据入口实质转向另一个。
4. 是否存在已经完成的工作被后续搜索吞并。

只有这些检查均不支持独立动作边界时，才可将相关工作合并为一个Stage。

不能只写“仍然解决相同问题”作为KEEP理由。

## 5. 边界判定优先级

先判断是否发生实际思维动作转换，再判断相邻内容是否属于同一次连续工作。

- 已实际展开的独立认知工作，优先保留。
- 普通查询重试、直接结果解释和同一次论证内部步骤，优先保持完整。
- 存在合理歧义时，保留主方案与备选方案及原文依据，不强行增减Stage。

所有Stage仍按真实时间顺序排列，不建立树状结构，不预设Stage数量，不提前判定冗余。

## 6. 典型校准案例

**N224：** 不能因为7次搜索围绕同一比赛缺口，就全部合并。需要识别人物假设核查、赛卡核查、实质候选排除及重新取证之间的转换。但也不能强制每次Call独立成Stage。

**N036：** 如果两次搜索之间只有重复的取证计划和轻微关键词变化，没有新的实质判断，可以归入同一Stage，同时完整保留两次真实Call与Return。

**N311：** 完整比较候选条件与随后执行针对性搜索，是两个不同工作动作，应分别识别。

这些案例用于检验通用规则，不应将它们的具体Stage数量或切点写成通用要求。
