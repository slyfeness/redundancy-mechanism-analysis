# ROOT_019 批内机制对照

十个Stage、十题、十原轨迹、40条实际续跑；八首句、两末段无引导。四条353为字符精确局部重编码，生成净差只给区间。全部单案独立手写保存并引用/成本检查，详见BATCH_ANALYSIS.json及机器复算BATCH_COUNTS.json。

关键不是“有无重做”，而是原具体产物及它如何进入后续：

1. **已完成与尚未完成的同名核验不同。** 78名字和够答判断都已在P，四次零Call仍提交；87河名/分类、55学院年还不在P，四次都真取回。55三次无Final不是学院事实丢失，而是后续首卷/职位未闭工作持续。
2. **认知重建与文字压缩并存。** 191/228无G末段四支都再做完整条件比较；191两支认节目获奖不等presenting而增加两真查，另两短答；228只小幅字短。不能按四C说全部认知省掉，也不能按FULL否认字数压缩。
3. **解释变成任务才解释额外成本。** 69新1同轮曾正确读spouse又误移本人美国出生，实际多查本人；最后修复C。3424和4272都识别了确切年份冲突，仍真查并正式接受同候选；不是没发现冲突，而是它没限制后面选择。
4. **联合返回是局部执行方式，不是总结果保证。** 55新1/2同一Call供学校1818与期刊2009并实际采用，原独立校史步骤取消；一个N且更贵、一个C且省。87原本也联合查两关系，不能为了新机制把它重复算新合并。
5. **部分匹配何时被当足够身份依据。** 353明知三生平未证，仍以书主题/日期为core；427明知年龄/并购/面积未证或产品日期不合，仍以最接近/大部分匹配正式选公司。两题内均有另一支继续查到N。成本下降常来自未完成核验的提前结束，一些分支生成仍更长。
6. **正确资料返回不等采用完整答案。** 592两支实际选举资料使下一Call转Jonathan并得到29May2015，但死者/原话/调查关系没闭，继续查而N。不能替模型从Return取日期冒充Formal，也不把两Call同批伪造为顺序决策。

新增候选N008只收有明确部分身份条件升为core/primary/closest/most且Formal选择的源证据；与N007频率作证可重叠但不同，不把所有gap+Final一概合并。反例、未确定、G和采样解释保留，Codex自审不等研究者验收。
