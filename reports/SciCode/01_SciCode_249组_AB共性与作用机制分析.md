- **首次形成算法或实现（BUILD）**：此前当前实现尚不存在，U把公式、科学关系或接口具体化。它可能先产生认知草稿，再由后续保存；不能一概叫重复确认。
- **已有方案首次落实状态（EXECUTE）**：明确算法已在P，U实际write/submit，让后续有可调用、可交接的代码。
- **验证与接受（VERIFY）**：候选已存在，U尝试运行、处理直接反馈并可能正式提交。入口拒绝与真正数值执行分开记录。
- **异常诊断和修订（DIAGNOSE）**：围绕已见异常选择该改什么；原解释或改法本身也可能错误。
- **重新展开既有判断（REOPEN）**：再次比较接口、关系、约束或接受理由；确有认知工作，但未必形成新产物。
- **确认并交付（HANDOFF）**：查看已保存状态、停止修改、提交当前版本，不是首次建立科学关系。

**A/B的差异不能仅从工作名称读出。** 首次实现删除后可以重建；验证删除后可以保留P中的正确稿；同样叫诊断的Stage，既可能消除真实缺陷，也可能把测试入口失败误当算法问题。下面分别追踪具体过程。

## A类为什么多数结果保持

先区分三种可以重叠的条件：核心正确关系已经在P；被删功能后来重新执行或由不同实现完成；最终评分对象根本没有调用被删helper。这些条件分别有多少组观察记录，见后面的观察链表，不能相加当互斥分类。

**已有正确稿时，减少的有时是一次绕路，而不是必要数学。** `33__step1__S003`中，P已有正确Hamiltonian。真实报错指测试脚本导入`haldane`，原U虽说“the error says IMPORT_DENIED with root haldane”，仍改掉候选的合法依赖和返回容器；后续继续从同一错误入口加载。删后四次都改成合法内联执行，再交正确公式。原write/run/read/submit变成run/submit：减少的明确是无效改写和读回，验证功能仍在。证据：原R3 `/steps/0/rounds/2/reasoning_content`；原E4 `/steps/0/tool_events/3/model_visible_return/validation/root`；四次各自的实际Call与返回见本组记录。

**有些重复判断只把已有采用再说一遍。** `34__step2__S005`删除前，电中性关系已写入正确代码，真实输出也在P，模型已初步接受。U再代入同一等式，解释残差后交同版；四次无引导续跑均保留原计算、较短确认后提交。这里可以说完整代数展开没有再次改变代码；不能说完全没有接受判断，也不能说省了真实测试，因为原U本来没有run。原R1 `/steps/1/rounds/0/reasoning_content`包含`N_a * x_p = N_d * x_n`，原R3在`/steps/1/rounds/2/reasoning_content`再次展开代数。

**首次实现被删但重做成功，不是功能不存在。** `11__step10__S003`四次均先按G测试空草稿，被`write_code must succeed before run_python`拒绝，随后重新实现multi。构造方式、测试质量和最终helper并不相同；最后entropy独立计算输入rho，仍全部C。四次生成加G反而都增加。这组不能叫“初态构造冗余”。它揭示的是功能恢复与评分依赖范围共同允许目标结果保持。

**A类内部也有强反例。** `77__step3__S006`四次都C：一条直接交P；一条合法真测；另一条把自造最小镜像预期当规范，又误记测试输入，围绕不存在的缺陷长篇推演和改写，后来才承认测试可能错并回到正确稿。相同结果既可更短，也可大幅增耗。该例是无G终端条件，仍不能把“答案不变”直接等同“工作省掉了”。

## B类为什么多数状态改变

**首先有真实的科学/接口判断变化。** `31__step1__S001`把题目“along the row”解释成“for each column”，实际写`D = X - X.mean(axis=0)`，拟验证也沿列检查。错误解释同时控制程序和检查方向。删后四次都采用axis1，其中三次C，一次虽然已写对却没有正式提交。前者说明约束落实影响程序，后者说明正确实现与完成提交是不同环节。源：原R1 `/steps/0/rounds/0/reasoning_content`、原E1代码及四新对应字段。

`41__step2__S004`中，U将资源关系反向理解，因自拟例子可能有负值而接受逐元素倒数列；原后续只修数值细节，保留错算子。删后四条都选择题面实际正向映射`M[:,j]`并保持到代码，全部C。变化不是“少做了比较”，而是从不充分的物理合理性解释，改为让题目明确的输入—输出关系约束算子选择。原U `/steps/1/rounds/0/reasoning_content`有“inverse of that species' conversion efficiency”及接受该方案的完整理由。

**也有正确判断恢复了，却没变成最终产物。** `36__step2__S004`四次都按G选择并实际保存过quad；新1、新2、新4正式又提交polylog而W，新3最终保留quad并真测后C。因此不能解释成“三次不知道积分方法”。差异是已采用的修法有没有继续约束最终提交。G本身提前给quad方向，不能把四次最初选择当作自主重新发现；四条对原测试功能的恢复也不相同。原U的真实失败本来指测试模块根，直接反馈却说`scipy.special`被拒，错误归因与后来有效方法选择须分开。

**许多B的远端变化无法归到被删U的独特作用。** 若删除的是前一子题验证，四次仍交同码、下一子题Prompt逻辑也相同，后来目标却以新seed选择了不同公式，那么可以解释目标代码哪里错，却不能说原验证通过那个错误改变了目标。`36__step2__S002`、`41__step2__S003`、`65__step4__S002`均保留这种反证。全部B组都在索引中，未因不符合“关键Stage”叙述而排除。

此外，N到W常见于原路径长篇草拟而未write/submit，新路径终于交出了错误程序；有正式答案和科学正确不是同一变化。凡是无法定位U到远端决策的桥，本报告明确保留未知，不用“工作重建”“预算循环”补上因果解释。

## 从实际材料得到的三条候选过程链

以下不是预置分类，也不主张已经识别删除U的唯一因果效应。观察链统计包括原U及新后续中确实可见的局部过程，**不能把组内后续观察数写成“这么多被删Stage都通过这一机制改变了答案”**。

### 解释同时决定实现和验收对象

**前态尚未落实具体约束 → U/新路径选择轴、角色、量纲或子空间 → 该解释进入程序及自写测试 → 与该解释自洽的弱测试不能排除错误 → 错实现被接受，或持续追求错误预期。**

`31`的行/列、`41`的正反映射是不同题目的直接局部对照。`11`的单激发子空间中，形状、trace、纯度都能正确，却仍可能投到错误基集合，说明通用性质不够区分题目要求。反面见`77`：正确最小镜像也可能因错误Expected被当作坏稿。关键共同点是判据是否真的来自题目及所检验对象，而不是有没有测试、测试次数多少。

这条链既能造成错误接受，也能制造不存在的待修任务；后者使Token增长，但不一定让最终答案变错。不能把所有T轴记录都叫U造成的效应。

### 反馈被解释成哪项任务，决定下一步是否有效

**已有候选 → 实际返回只说明测试入口不合法 → 模型把它提升为候选依赖/算法故障 → 改掉未出错部分，却沿用被拒入口 → 没有新科学反馈，验证缺口继续派发调用。**

`33__step1__S003`四次直接合法执行的反向对照最清楚；`32`、`67`等不同题目也有入口根与候选依赖被混同的原文。必要限制是：第一次调整入口、实际修复真正依赖缺失，属于有效工程工作；不能因为存在重试就归为无效。

反馈解释改对后，即使功能仍要重新执行，绕路也可以减少；改错时，保存状态或未调用目标函数的OK又可能被当成足够交付。因此“重建了”既不能否认执行压缩，也不能证明恢复了有效判断。

### 正确认识只有保持到被执行及正式版本，才改变后续状态

**冲突/公式修法已识别 → write保存某版 → run实际执行某版 → 用返回接受某版 → submit及下一子题消费某版。**

任一对应丢失，模型可以说对、临时测对，却让旧错误继续进入下一步；真实反馈甚至会被误用来推翻已经改好的内容。`36__step2__S004`四次的3W/1C直接说明方法认识都恢复而正式保持不同；`11__step10__S003`新4的measurement写对角修复却正式交旧crosspairs，是另一个明确节点。后者目标仍C，是评价依赖范围不覆盖该helper的反例，不能拿它证明该失配必然改变最终C/W。

这条链连接的是可观察的日志状态，不猜测隐藏信心。它能解释哪些修复没有生效、为何同错继续引发工作；它不能自动解释最早一次Stage删除为什么促成更晚的版本选择。

## 如何复核及完成状态

`STAGE_INDEX.csv`覆盖全部组，`BRANCH_RESULTS_AND_COSTS.csv`逐条连接官方状态、成本和Codex原样判断；`MODEL_REVIEWS/`保留全部逐组原文证据位置、四路径分析和反例。原始大轨迹仍保留在本机已下载材料和正式实验目录，不因报告精简而删除。包内源路径/SHA/JSON Pointer使每项判断可追溯，不以本报告摘要替代原始实验。

`aggregate_sealed_reviews.py`只连接封存语义记录、验证状态/成本算式并统计；手工索引由Codex逐份阅读后写入，不根据关键词、Query相似度或默认值生成语义结论。规则未改，旧结果未覆盖。

完成的是全范围逐组语义自审、确定性连接/计数和供研究者审核的候选过程解释。**没有宣称研究者人工金标准、纯删除因果证明或所有Stage都已获得唯一机制解释。** 待判断问题主要是：G完成姿态/未来任务对行动的补偿或干扰，原U与远端新决策缺少唯一桥，局部正确与目标评分范围的脱钩，以及题面本身存在单位/接口冲突。
