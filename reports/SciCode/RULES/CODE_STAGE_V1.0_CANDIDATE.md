# CODE_STAGE_V1.0_CANDIDATE

本文件是本次五条试切的固定执行快照，依据研究者在本对话认可的编程Stage方案；试切期间不修改。它不替代原CONTINUOUS_WORK_STAGE V1.3.2冻结文件，不表示已经通过研究者验收。

## 1. 定义

Stage是模型沿真实时间连续完成的一项相对完整的编程工作，包含该项工作的推理、代码操作、真实调用、完整模型可见返回和直接结果解释。按当前对象、要解决的问题、实际做法识别；对象相同不必然KEEP，做法变化不必然SPLIT。不按Round、函数数、代码行、调用数或Token数切分，不预设数量，不建树。

结构：题目与实际输入 → S001 → S002 → …… → 正式提交或真实终态。

## 2. 边界决策

依次检查：前一工作是否形成局部结果或被打断；后一段是否已经实际分析、推导、比较、操作代码、执行测试或形成提交决策；后一段是否仅为前一工作的自然延续。直接结果解释、落实刚确定的修正、输入笔误处理和同一操作继续通常KEEP；实际开始新的问题判断、算法选择、错误假设验证或独立核验则SPLIT。仅提及未来任务不算执行。每个SPLIT说明前后具体工作以及为何不是内部步骤。

## 3. 场景判定

连续理解输入输出、数学要求并形成实现方案可保持完整。形成方案后独立比较另一算法、否定原假设、重新推导时审核新边界；列举备选不自动切分。

为落实同一实现方案的推导、写代码、直接检查通常保持完整；不按文字/代码转换或函数数切分。转向另一个独立问题，如数值稳定性，应检查真实转换。

伴随实现的形状、索引、语法或小计算检查通常留在实现工作。候选实现完成后独立设计验证，选择测试条件、期望结果并判断要求，应另建Stage。一次测试的设计、运行、完整返回、直接解释保持完整。

明确拼写、括号、调用格式错误的直接修正重试通常KEEP。根据报错提出新错误假设并追踪、比较或推导原因，在诊断实际开始处SPLIT；已确定原因后的修复及直接验证通常与本次诊断修复保持完整。不同错误假设不能一律并入“继续调试”。

同一次运行状态查询、无新判断的原样重试、同一测试计划的一组输入、同一操作轻微调整通常KEEP。前次结果得到解释后提出新的测试问题、专门核验另一条件、修改错误假设后重新设计验证、接受后再次实际核查时审核SPLIT；不以字符串相似度判断。

单输入通过、维度不符等是局部反馈。实际综合判断关键要求、已验证/未验证条件、保留算法、继续修改或正式提交时，识别独立判断。简单复述与简短信心不自动切分。

单纯submit_code提交刚确定的代码不自动建立新Stage，可为当前工作结束。提交前实际重新组织实现、修改接口、合并组件或展开整体验收时依真实工作切分。准备提交不等于正式提交。

## 4. 原文、工具及代码状态

保存逐字段Unicode字符范围[start,end)、原文和SHA。Call、参数内完整代码、Return不切开。真实工具批次保留共同决策、实际执行顺序，不虚构批内看到结果后的新决策。单个Call多功能整体保留并注明主要/附带工作。代码块内部无可靠思维边界时不按函数强拆。

逐Stage记录开始代码版本、实际读写/修改/提交、测试运行版本、结束代码版本及未解决问题。磁盘完整输出和Actor实际可见输出分别标记；不把未返回内容当成已知。无显式Reasoning的操作据真实Call记录，不补动机。正式提交产物单独索引，Call/Return唯一归属。

## 5. 时序与子问题

A被B打断后恢复A建立新的连续实例，不跨B合并。子问题编号+Round+字段位置共同定位。记录新会话实际收到的历史代码与上下文，不假定此前推理持续可见。新子问题或新会话开始新的Stage实例；官方step不等于语义Stage，未执行子问题不补造。

## 6. 终态与正确性

允许工作完成、失败、仍未解决、被打断、正式提交和真实预算/上下文/其他终止。保存接受不等于自测通过、不等于满足要求、不等于官方评分通过。官方评分仅作事后信息，不倒推当时认知或调整切点。

## 7. 工作流与验收

完整阅读所有实际输入、Reasoning、代码、Call/Return及终态；先重建求解过程，再确定动作和切点；逐边界KEEP/SPLIT；长Stage反查独立诊断/验证/提交判断，短Stage反查是否切碎同次实现/测试/修复；核验原文全覆盖、无重叠、SHA、工具唯一归属、代码版本和执行顺序。歧义保留主方案及备选；没有可观察的独立起点时保持完整工作，不猜测新增边界。语义自审不等于独立人工验收。
